# Gradle Version Catalog (libs.versions.toml)

## Purpose

Define that Every microservice MUST **always** generate the `gradle/libs.versions.toml` file as the standard mechanism for centralizing all dependency and plugin versions in the project. Hardcoded versions in `build.gradle` or `gradle.properties` are not accepted.

## Scope of Application

- In every Java project included in every project.
- Applies to all archetypes: imperative hexagonal, reactive hexagonal, serverless.
- Client-independent.

## Main Content

### What It Is

The Gradle Version Catalog is a TOML file (`gradle/libs.versions.toml`) that centralizes:
- **Versions** of all dependencies and plugins.
- **Library aliases** to reference from any `build.gradle` with `libs.<alias>`.
- **Plugin aliases** to apply with `alias(libs.plugins.<name>)`.

### Mandatory Location

```
project/
├── gradle/
│   └── libs.versions.toml    ← MANDATORY in every project
├── build.gradle               ← Uses aliases: libs.<name>
├── settings.gradle
└── ...
```

### File Structure

The file has 3 sections:

```toml
# gradle/libs.versions.toml

# ─── 1. VERSIONS — All centralized versions ──────────────────
[versions]
spring-boot = "4.0.3"
spring-dependency-management = "1.1.7"
lombok = "1.18.36"
jspecify = "1.0.0"
reactor-test = "3.7.6"
springdoc = "2.7.0"

# ─── 2. LIBRARIES — Dependency aliases ───────────────────────
[libraries]
# Spring Boot starters
boot-starter-webflux = { module = "org.springframework.boot:spring-boot-starter-webflux" }
boot-starter-webmvc = { module = "org.springframework.boot:spring-boot-starter-webmvc" }
boot-starter-actuator = { module = "org.springframework.boot:spring-boot-starter-actuator" }
boot-starter-validation = { module = "org.springframework.boot:spring-boot-starter-validation" }
boot-starter-test = { module = "org.springframework.boot:spring-boot-starter-test" }
boot-starter-opentelemetry = { module = "org.springframework.boot:spring-boot-starter-opentelemetry" }

# Reactor
reactor-core = { module = "io.projectreactor:reactor-core" }
reactor-test = { module = "io.projectreactor:reactor-test", version.ref = "reactor-test" }

# Lombok
lombok = { module = "org.projectlombok:lombok", version.ref = "lombok" }

# JSpecify (null-safety)
jspecify = { module = "org.jspecify:jspecify", version.ref = "jspecify" }

# Documentation
springdoc-webflux = { module = "org.springdoc:springdoc-openapi-starter-webflux-ui", version.ref = "springdoc" }
springdoc-webmvc = { module = "org.springdoc:springdoc-openapi-starter-webmvc-ui", version.ref = "springdoc" }

# Testing
junit-platform-launcher = { module = "org.junit.platform:junit-platform-launcher" }

# ─── 3. PLUGINS — Plugin aliases ─────────────────────────────
[plugins]
spring-boot = { id = "org.springframework.boot", version.ref = "spring-boot" }
spring-dependency-management = { id = "io.spring.dependency-management", version.ref = "spring-dependency-management" }
```

### How to Use in build.gradle

**Root:**
```groovy
plugins {
    alias(libs.plugins.spring.boot) apply false
    alias(libs.plugins.spring.dependency.management) apply false
    id 'java'
}
```

**Submodules:**
```groovy
dependencies {
    implementation libs.boot.starter.webflux
    implementation libs.reactor.core
    compileOnly libs.lombok
    annotationProcessor libs.lombok
    implementation libs.jspecify
    testImplementation libs.boot.starter.test
    testImplementation libs.reactor.test
}
```

### Additional Dependencies by Stack

the developer composes the TOML by adding the standard base + dependencies according to the project's driven-adapters:

| Stack | Dependencies to add |
|-------|---------------------|
| R2DBC (PostgreSQL) | `r2dbc-postgresql`, `spring-boot-starter-data-r2dbc` |
| R2DBC (SQL Server) | `r2dbc-mssql`, `mssql-jdbc` |
| JPA (PostgreSQL) | `postgresql`, `spring-boot-starter-data-jpa` |
| MongoDB Reactive | `spring-boot-starter-data-mongodb-reactive` |
| Kafka / MSK | `spring-kafka` |
| AWS SDK | `aws-secretsmanager`, `aws-ssm`, `aws-sdk-sts` |
| Redis | `spring-boot-starter-data-redis-reactive` |


## Important Rules

- **Every project** generated by Every microservice MUST include `gradle/libs.versions.toml`.
- **Never** hardcode versions in `build.gradle` (neither `version '4.0.3'` nor inline `version.ref`).
- **Never** use `gradle.properties` to define dependency versions.
- Plugins are applied with `alias(libs.plugins.<name>)`, not with `id '...' version '...'`.
- Dependencies are referenced with `libs.<alias>`, not with coordinate strings.
- Spring Boot versions without `version.ref` inherit from the `spring-dependency-management` plugin.
