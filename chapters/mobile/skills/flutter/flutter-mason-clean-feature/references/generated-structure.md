# Generated Feature Structure

This reference describes the complete directory structure generated by the `flutter_clean_feature` brick and the responsibility of each file and folder.

**Note**: This brick is designed for Flutter monorepo projects. The structure assumes local workspace dependencies (`../../packages/...`, `../../shared/...`).

## Directory Tree

A typical feature generated with `name: profile` and `prefix: app`:

```
features/profile/
├── lib/
│   ├── profile.dart                         # Public API export file
│   └── src/
│       ├── data/
│       │   ├── datasources/                 # Data source layer
│       │   │   ├── data_sources.dart        # Barrel export file
│       │   │   ├── get_data_data_source.dart          # Abstract interface
│       │   │   ├── get_data_local_data_source.dart    # Local implementation
│       │   │   └── get_data_remote_data_source.dart   # Remote implementation
│       │   ├── models/
│       │   │   └── data_model.dart          # Data serialization models
│       │   ├── mappers/
│       │   │   └── get_data_mapper.dart     # Entity mappers
│       │   └── repositories/
│       │       ├── repositories.dart        # Barrel export
│       │       ├── get_data_repository.dart         # Implementation
│       │       └── get_data_repository.dart         # Abstract interface (domain/)
│       ├── domain/
│       │   ├── entities/
│       │   │   ├── entities.dart            # Barrel export
│       │   │   └── data_entity.dart         # Domain entity
│       │   ├── repositories/
│       │   │   ├── repositories.dart        # Barrel export
│       │   │   └── get_data_repository.dart         # Abstract interface
│       │   └── usecases/
│       │       └── get_data_usecase.dart    # Business logic (use case)
│       ├── presentation/
│       │   ├── blocs/
│       │   │   ├── blocs.dart               # Barrel export
│       │   │   ├── profile/
│       │   │   │   ├── profile_cubit.dart   # State management (Cubit)
│       │   │   │   └── profile_state.dart   # State definitions (if applicable)
│       │   ├── pages/
│       │   │   ├── pages.dart               # Barrel export
│       │   │   └── profile/
│       │   │       └── profile_page.dart    # Full screen widget
│       │   └── widgets/
│       │       └── (custom reusable widgets)
│       ├── routes/
│       │   ├── routes.dart                  # Barrel export
│       │   ├── profile_routes.dart          # GoRouter routes list
│       │   └── enum/
│       │       └── app_routes.dart          # Route enum definitions
│       └── di/
│           ├── injector.dart                # GetIt setup
│           └── feature_register_module.dart # Injectable @module
├── test/
│   └── src/
│       ├── data/
│       │   ├── datasources/
│       │   ├── models/
│       │   ├── mappers/
│       │   └── repositories/
│       ├── domain/
│       │   └── usecases/
│       └── presentation/
│           └── cubits/
## File Descriptions by Layer

### Root Files

#### `pubspec.yaml`
Feature-specific pub package configuration with:
- Workspace resolution (if part of monorepo)
- Dependency declarations (packages, shareds as local paths)
- SDK constraints
- Flutter configuration

**You modify this to**: Add new dependencies, though most are configured via the JSON config file during generation.

#### `analysis_options.yaml`
Lint rules for the feature. Follows project-wide linting standards.

**You typically don't modify** unless adding feature-specific lint configurations.

#### `build.yaml`
Build Runner configuration for code generation (GetIt, Injectable).

**You modify this if**: Adding custom builder configurations.

#### `README.md`
Feature documentation. Should describe:
- Feature purpose and scope
- Key public APIs (entities, cubits, routes)
- How to use the feature from other features/apps
- Implementation notes and assumptions

### `lib/profile.dart` (Public API)

**Most important file**. Exports all public classes that external packages can import:

```dart
library;

export 'src/domain/entities/entities.dart';     // Domain models
export 'src/domain/repositories/repositories.dart';  // Abstract repos
export 'src/presentation/blocs/blocs.dart';    // Cubits/BLoCs
export 'src/presentation/pages/pages.dart';    // Page widgets
export 'src/routes/routes.dart';               // Feature routes
export 'src/di/injector.module.dart';          // DI configuration
```

**Key responsibility**: Controls what's available to external consumers. Only export public APIs.

**Do NOT export**: 
- Concrete data source implementations
- Repository implementations
- Internal widgets or helper functions

#### Data Sources (`src/data/datasources/`)

**Files**:
- `data_sources.dart` - Barrel export file
- `get_data_data_source.dart` - Abstract interface defining the contract
- `get_data_local_data_source.dart` - Local implementation (cache, database)
- `get_data_remote_data_source.dart` - Remote implementation (API calls)

**Responsibility**:
- Fetch or store raw data from external sources
- Handle serialization/deserialization if needed
- Throw exceptions on failures
- Implementations are NOT exported in public API

**Example pattern**:
```dart
// Abstract
abstract class GetDataDataSource {
  Future<dynamic> get();
}

// Local
class GetDataLocalDataSource implements GetDataDataSource { }

// Remote
class GetDataRemoteDataSource implements GetDataDataSource { }
```

### Root Files

#### `pubspec.yaml`
Feature-specific pub package configuration. Includes:
- Dependency declarations (`commons`, `http`, etc.)
- SDK constraints
- Flutter configuration

**You modify this to**: Add new dependencies, configure dev_dependencies for tests

#### `analysis_options.yaml`
Lint rules for the feature. Extends project-wide rules.

**You typically don't modify this** unless adding feature-specific lint rules

#### `build.yaml`
Build Runner configuration. Used by `dart run build_runner build` to generate code.

**You modify this if**: Adding custom builder configurations or code generators

#### `README.md`
Feature documentation. Describe:
- Feature purpose and scope
- Key entities and business rules
- How to use the feature (routes, exported classes)
- Implementation notes

### `lib/profile.dart` (Public API)

**Most important file**. Exports all public classes from the feature:

```dart
export 'src/domain/entities/profile_entity.dart';
export 'src/presentation/cubits/profile_cubit.dart';
export 'src/routes/profile_routes.dart';
export 'src/di/profile_module.dart';
```

**Key responsibility**: Controls what external packages can import. Only export:
- Cubits/BLoCs (for UI consumption)
- Entities (for domain knowledge)
- Routes (for router integration)
- DI Module (for service locator setup)

**Do NOT export**: Internal implementation details (data sources, repository implementations, abstract repositories)

### Data Layer (`src/data/`)

#### Responsibility
Concrete implementation of data retrieval and storage. Handles:
- API calls (remote)
- Local database queries
- Data serialization/deserialization
- Caching strategies

**Dependency flow**: Domain ← Data ← Presentation

#### Directories

##### `data_sources/`

###### `remote/app_profile_remote_data_source_interface.dart` (Interface)

Abstract class defining remote data operations:

```dart
abstract class AppProfileRemoteDataSource {
  Future<dynamic> getProfile(String userId);
  Future<void> updateProfile(dynamic profileData);
}
```

**Responsibility**:
- Define contracts for remote operations
- No implementation details
- Allow testing through mocking

###### `remote/app_profile_remote_data_source_impl.dart` (Implementation)

Concrete implementation using HTTP client, Dio, GraphQL, etc.:

```dart
class AppProfileRemoteDataSourceImpl implements AppProfileRemoteDataSource {
  final http.Client _httpClient;
  
  Future<dynamic> getProfile(String userId) async {
    final response = await _httpClient.get('/users/$userId');
    return json.decode(response.body);
  }
}
```

**Responsibility**:
- Handle network requests
- Parse responses
- Throw exceptions on errors

###### `local/app_profile_local_data_source_interface.dart` & `_impl.dart`

Similar pattern for local data (SQLite, Hive, SharedPreferences, etc.)

##### `repositories/`

###### `app_profile_repository_interface.dart` (Abstract)

Abstract repository interface matching domain layer:

```dart
abstract class AppProfileRepository {
  Future<Result<AppProfileEntity>> getProfile(String userId);
  Future<Result<void>> updateProfile(AppProfileEntity profile);
}
```

**Responsibility**:
- Mirror domain repository interface exactly
- Define data contracts
- Imported by domain layer (abstract)

###### `app_profile_repository_impl.dart` (Implementation)

Implements domain repository using data sources:

```dart
class AppProfileRepositoryImpl implements AppProfileRepository {
  final AppProfileRemoteDataSource _remoteDataSource;
  final AppProfileLocalDataSource _localDataSource;
  
  Future<Result<AppProfileEntity>> getProfile(String userId) async {
    try {
      final remote = await _remoteDataSource.getProfile(userId);
      await _localDataSource.save(remote);
      return Result.success(AppProfileEntity.fromMap(remote));
    } catch (e) {
      return Result.failure(e);
    }
  }
}
```

**Responsibility**:
- Orchestrate data sources (remote/local)
- Implement caching and fallback strategies
- Convert data source outputs to domain entities
- Handle errors and return Results

### Domain Layer (`src/domain/`)

#### Responsibility
Pure business logic, platform-agnostic. Contains:
- Entities (data models)
- Abstract repositories (interfaces)
- Use cases (business rules)

**No imports from**: data or presentation layers

#### Directories

##### `entities/app_profile_entity.dart`

Value object representing a profile in the domain:

```dart
class AppProfileEntity {
  final String id;
  final String name;
  final String email;
  
  AppProfileEntity({
    required this.id,
    required this.name,
    required this.email,
  });
}
```

**Responsibility**:
- Represent domain concepts in code
- Immutable (use value_equality or equatable)
- No JSON serialization (that's data layer's job)
- No business method complexity (keep it simple)

##### `repositories/app_profile_repository.dart`

Abstract repository interface (no implementation):

```dart
abstract class AppProfileRepository {
  Future<Result<AppProfileEntity>> getProfile(String userId);
  Future<Result<void>> updateProfile(AppProfileEntity profile);
}
```

**Responsibility**:
- Define data access contracts
- Abstract away data source implementation
- Allow testing without real data sources

##### `use_cases/get_profile_use_case.dart`

Encapsulates a single business operation:

```dart
class GetProfileUseCase {
  final AppProfileRepository _repository;
  
  GetProfileUseCase(this._repository);
  
  Future<Result<AppProfileEntity>> call(String userId) async {
    if (userId.isEmpty) return Result.failure(Exception('Invalid user ID'));
    return await _repository.getProfile(userId);
  }
}
```

**Responsibility**:
- Implement business logic
- Validate inputs
- Call repositories
- Be testable (unit tests only, no mocks)

**One responsibility per use case**: Prefer `GetProfileUseCase` over `ProfileUseCase` with multiple methods

### Presentation Layer (`src/presentation/`)

#### Responsibility
UI and state management. Contains:
- Pages (full screens)
- BLoCs/Cubits (state management)
- Widgets (reusable components)

**Imports**: Domain + Presentation layers only

#### Directories

##### `pages/app_profile_page.dart`

Full screen widget:

```dart
class AppProfilePage extends StatelessWidget {
  const AppProfilePage({Key? key}) : super(key: key);

  @override
  Widget build(BuildContext context) {
    return BlocProvider(
      create: (context) => getIt<AppProfileCubit>(),
      child: const AppProfileView(),
    );
  }
}

class AppProfileView extends StatelessWidget {
  const AppProfileView({Key? key}) : super(key: key);

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Profile')),
      body: const AppProfileBody(),
    );
  }
}
```

**Responsibility**:
- Wrap widgets in BlocProvider
- Define page structure (AppBar, Scaffold)
- Connect to state management

##### `cubits/app_profile_cubit.dart` (State Management)

Manages feature state using Cubit pattern:

```dart
class AppProfileCubit extends Cubit<AppProfileState> {
  final GetProfileUseCase _getProfileUseCase;
  
  AppProfileCubit({required GetProfileUseCase getProfileUseCase})
      : _getProfileUseCase = getProfileUseCase,
        super(const AppProfileState.initial());
  
  Future<void> getProfile(String userId) async {
    emit(const AppProfileState.loading());
    final result = await _getProfileUseCase(userId);
    
    result.fold(
      (failure) => emit(AppProfileState.error(failure.toString())),
      (profile) => emit(AppProfileState.success(profile)),
    );
  }
}
```

**Responsibility**:
- Manage feature state
- Call use cases
- Emit state changes
- Handle loading/success/error states

##### `cubits/app_profile_state.dart` (State Definition)

Defines possible states using freezed or sealed classes:

```dart
@freezed
class AppProfileState with _$AppProfileState {
  const factory AppProfileState.initial() = _Initial;
  const factory AppProfileState.loading() = _Loading;
  const factory AppProfileState.success(AppProfileEntity profile) = _Success;
  const factory AppProfileState.error(String message) = _Error;
}
```

**Responsibility**:
- Define all state variants
- Use discriminated unions (freezed/sealed)
- Immutable and copyable

##### `widgets/app_profile_body.dart`

Reusable widget components:

```dart
class AppProfileBody extends StatelessWidget {
  const AppProfileBody({Key? key}) : super(key: key);

  @override
  Widget build(BuildContext context) {
    return BlocBuilder<AppProfileCubit, AppProfileState>(
      builder: (context, state) {
        return state.maybeWhen(
          success: (profile) => Column(
            children: [
              Text(profile.name),
              Text(profile.email),
            ],
          ),
          loading: () => const CircularProgressIndicator(),
          error: (message) => Text('Error: $message'),
          orElse: () => const SizedBox.shrink(),
        );
      },
    );
  }
}
```

**Responsibility**:
- Build UI based on state
- Listen to state changes via BlocBuilder
- Delegate navigation to routes

### Routing (`src/routes/app_profile_routes.dart`)

Defines all feature routes:

```dart
abstract class AppProfileRoutes {
  static const String profilePage = '/profile';
  
  static final routes = [
    GoRoute(
      path: profilePage,
      builder: (context, state) => const AppProfilePage(),
    ),
  ];
}
```

**Responsibility**:
- Export all routes as a static list
- Import in app's router configuration
- Define all feature screens accessible from outside

### Dependency Injection (`src/di/`)

#### Responsibility
Configure GetIt scope for the feature.

##### `app_profile_module.dart`

@Module class for injectable code generation:

```dart
@module
abstract class AppProfileModule {
  @lazySingleton
  AppProfileRepository appProfileRepository(
    AppProfileRepositoryImpl impl,
  ) =>
      impl;

  @lazySingleton
  GetProfileUseCase getProfileUseCase(AppProfileRepository repository) =>
      GetProfileUseCase(repository);

  @lazySingleton
  AppProfileCubit appProfileCubit(GetProfileUseCase useCase) =>
      AppProfileCubit(getProfileUseCase: useCase);
}
```

**Responsibility**:
- Declare all injectable dependencies
- Use @lazySingleton for most (created on first use)
- Use @singleton sparingly (created at startup)

##### `scope/app_profile_scope.dart` (Optional)

Initializes feature-specific GetIt scope:

```dart
Future<void> initAppProfileScope(GetIt getIt) async {
  // Additional setup if needed
}
```

**Responsibility**:
- Optional async initialization
- Can be empty

### Tests (`test/`)

Mirror `lib/src/` structure:

```
test/src/
├── data/
│   ├── repositories/
│   └── data_sources/
├── domain/
│   └── use_cases/
└── presentation/
    └── cubits/
```

**Convention**: For every `lib/src/` file, create `test/` file with `_test.dart` suffix

**Responsibility**:
- Unit tests for use cases and repositories
- Widget tests for pages and widgets
- Follow AAA pattern (Arrange, Act, Assert)

## Summary: Which Files to Modify

| File | Priority | When |
|------|----------|------|
| `lib/profile.dart` | ⭐⭐⭐ | Export new public APIs |
| `src/domain/` | ⭐⭐⭐ | Define entities, repositories, use cases |
| `src/data/` | ⭐⭐⭐ | Implement repositories, data sources |
| `src/presentation/` | ⭐⭐⭐ | Build UI and state management |
| `src/routes/` | ⭐⭐ | Add new routes |
| `src/di/` | ⭐⭐ | Register new dependencies |
| `pubspec.yaml` | ⭐⭐ | Add dependencies |
| `test/` | ⭐⭐ | Add tests (TDD) |
| `README.md` | ⭐ | Document feature |
| `analysis_options.yaml` | - | Usually don't modify |
| `build.yaml` | - | Usually don't modify |
